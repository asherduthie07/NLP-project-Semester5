# Extraction evaluation and independent review workflow

Status: **REVIEW_PENDING**, reviewed files/annotations: **0**. No independent precision, recall or F1 is currently measurable. The implementation is `analyzers/evaluation.py`; CLI is `scripts/extraction_evaluation.py`; package is `datasets/evaluation/`. Its seven synthetic MIT fixtures expand the existing asserted examples. No human identity or approval has been supplied or invented.

`prepare` runs the real import/preprocess/structural pipeline in an isolated database and stores immutable initial analyzer candidates, a source hash manifest, Pydantic JSON schema, empty source-only labeling forms, pending sign-off and a disagreement log. It refuses to overwrite existing files. `evaluate` regenerates current predictions. While review is pending it writes metrics null; it does not score candidates against themselves. When a reviewer supplies approved labels, it validates the sign-off, source/label hashes, reviewed file coverage, disagreement state and relationship identity consistency before scoring. Recorded provenance is an attestation, not cryptographic proof of the reviewer's identity. Independent labeling instructions are in `datasets/evaluation/GUIDELINES.md`.

Exact symbol matching uses file path/hash/language, category, qualified name, complete half-open Unicode span, signature and parameter list. Only whitespace in signatures is collapsed; Java overload signatures remain distinct. Relationship matching includes occurrence span, category, embedded source/target symbol identities, target spelling, alias and resolution status. A wrong status or source span produces an FP and FN. Duplicate predictions are counted with multisets, so duplicates are not silently hidden.

TP is the multiset intersection, FP predicted-only occurrences, FN reference-only occurrences. Precision=TP/(TP+FP), recall=TP/(TP+FN), F1=2TP/(2TP+FP+FN). Undefined denominators produce JSON null, never an invented perfect score. Each population reports micro totals, per-language totals, per-category totals and macro P/R/F1 averaging defined categories only. Dependency totals include imports/inherits/implements/calls and exclude containment. False positive and false negative examples retain full labels. Empty categories appear explicitly. Hand-calculated evaluator unit tests are separate from corpus scoring and are not empirical extraction accuracy.

Current implementation inventory: Python AST emits modules, classes/nested classes, functions/nested functions, async methods, constructors, variable assignments and class fields. Java Tree-sitter emits file modules, class/interface/record/enum, methods/constructors with overload signatures, fields and locals. Parameters are signature metadata; standalone parameter extraction is absent. Both produce containment/import/inheritance/call candidates, Java implementation edges and explicitly conservative resolution. Tests cover aliases, circles, overloads, supported routes, empty/malformed input and persistence. The full category list in the review schema is intentionally wider than the currently emitted subset so omissions remain visible.

Confirmed defect fixed during package preparation: Python AST provides UTF-8 byte columns; structural CAIR mistakenly copied these into Unicode column fields. `analyzers/structure.py` now converts byte columns to code points. `test_python_unicode_structure_spans` verifies an identifier following an earlier non-ASCII identifier on the same line. Other extractor limitations remain documented and await independent reference review; no gold labels were adjusted to improve a score.

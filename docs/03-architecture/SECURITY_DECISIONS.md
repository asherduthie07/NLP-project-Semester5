# Security decisions and boundaries

Phase I treats all imported source as untrusted data. No eval, exec, compilation, import, shell execution, repository hooks, dependency install or submitted-code execution exists. AST parsing does not evaluate source. ZIP paths never reach the filesystem. Artifact names are hashes; atomic publication prevents concurrent readers from seeing partial writes, symlink reads are rejected, and hashes are checked before use.

GitHub requests have a fixed HTTPS host allowlist, validated global addresses, pinned destination IP with original verified TLS SNI/Host, disabled environment proxy trust, public-metadata check, exact commit download, no redirects and bounded bodies/deadlines. Public GitHub availability is not required in tests. Unsupported archive content is not executed and unsafe entries fail validation regardless of extension.

Controls include HTTP actual-body limits (also chunked requests), file/archive/token budgets, worker time limits, JSON-only task serialization, sanitized API failures, ignored local secrets/artifacts and non-root containers with dropped capabilities, read-only root filesystem, tmpfs and CPU/memory limits. An optional constant-time compared API key protects all endpoints. It is never embedded in the frontend.

Deployment boundary: empty-key loopback development is intentionally supported. Public multi-user exposure, per-project tenant access control, TLS termination, request rate/concurrency control, storage quotas/retention, backups, encrypted storage and operational monitoring require deployment hardening. Phase I does not claim these controls are implemented. Project/result list pagination and streaming large result responses are also future hardening work; current configured input budgets bound each import.

Known tradeoffs: artifacts plus metadata do not form a cross-filesystem transaction, so failures may leave orphaned immutable blobs. Local administrators can alter blobs/DB despite API immutability; subsequent hash checking detects blob alteration. DNS resolution itself relies on the host resolver, while the final validated IP is pinned for connection. Java Unicode escape translation is warned, not compiler-equivalent.

Dependency review: exact resolver-compatible versions are locked. React Router was updated to a patched 7.x version while retaining React 18. `openapi-typescript` 7.13.0 uses a scoped `@redocly/openapi-core` → `minimatch` 11.0.1 override to remove the reported glob amplification advisory; local schema generation, strict build and browser tests validate the used code path. This override is explicit and should be removed when upstream updates its dependency. No `--force`, legacy peer bypass, error suppression or lint-rule disabling is used. See execution results for actual audits and remaining environment limitations.

Version evidence: [PostgreSQL 17 release notes](https://www.postgresql.org/docs/17/release.html), [Redis releases](https://github.com/redis/redis/releases), [Redis archive hashes](https://github.com/redis/redis-hashes). Compose pins patched PostgreSQL 17.11 and Redis 7.4.12 tags. Local native PostgreSQL 14.17 was used only as an isolated test instance; separate recorded evidence now verifies PostgreSQL 17.11 container startup and the full Linux suite.
